Browser-side web packaging

  • HTML5/PWA packaging runs in the browser.
  • The exporter includes the game runtime and referenced assets, not the editor.
  • When asset optimization is supported by the browser, images/audio may be re-encoded and checked before inclusion.
  • The result is a downloadable ZIP. Use a local HTTP server or static host to run it; direct file:// opening is not supported.

Android APK workflow

The Android card uses the built-in service configured for this Realot deployment. The editor prepares the standalone game ZIP, requests or renews a temporary build token, uploads the ZIP, polls the job and downloads the APK. You do not add a custom build server or paste an API key into the Export window.

The card shows the service connection state and the remaining APK export allowance. The current client-side allowance is 3 accepted builds in a rolling 14-day window per browser; the authoritative service may apply additional server-side limits.

Progress and cancellation

While an APK is building, the Export window displays progress and offers Cancel build. The editor polls the job approximately every 2.5 seconds and uses a 10-minute client timeout. Cancelling or leaving the editor signals cancellation to the service when possible. HTML5 and PWA packaging occurs locally in the browser.

Build an APK from a web export

After an HTML5 or PWA export, the result screen can offer Build APK from this HTML5/PWA export. This sends the exact web ZIP already created, so the game package does not need to be rebuilt.
